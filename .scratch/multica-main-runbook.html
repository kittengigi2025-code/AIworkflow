Multica QA 主力执行规范

目标：以后需求测试主力交给 Multica，但产物必须能进入本地 Dashboard，并经过复验后再对外流转。
返回 Dashboard 测试军团

固定执行链路

阶段 负责人 必须产出 通过条件
需求提取 Requirement Extractor 需求事实、页面路径、已确认规则、阻塞问题 不补脑；不问文档已说明的问题；只留下影响通过/失败判断的问题。
疑问闸门 Question Gatekeeper 可直接发给产品/开发的阻塞问题 没有阻塞问题才允许进入测试设计；有阻塞问题则先等待确认。
测试设计 Test Designer 测试点、步骤、预期、证据要求、优先级 覆盖主流程、空值、0 值、分页、筛选残留、弹框关闭、前后台一致性。
浏览器执行 QA 浏览器执行员 测试报告、截图证据、发现问题 只做只读操作；不处理验证码、密码、资金、审批、保存、导出等敏感动作。
Bug 提炼 Bug Writer 独立 Bug 单 HTML 每个 Bug 必须有步骤、预期、实际、影响、责任初判、截图证据。
复验门禁 QA 复验专家 复验报告或关闭说明 新 Bug、误报、非 Bug、回归通过/失败都必须有复验结论。
台账发布 Ledger Keeper Dashboard 数据、报告入口、下载包 通过 npm run qa:publish；Dashboard 能看到需求、问题轨迹和下载入口。

每次派给 Multica 的标准要求

输入 需求截图、文档链接、前后台地址、已登录状态说明、产品/开发补充口径。
输出目录 .scratch/multica-runs/<requirement-slug>-<yyyymmdd>/，不要输出到不可访问的插件临时路径。
报告格式 只交 HTML：question-gate.html、test-design.html、test-report.html、bug-tickets.html、regression-report.html。
截图位置 统一放在 evidence/，并嵌入到对应 Bug 或用例结果下面，不做孤立图库。
浏览器边界 常规查看、点击菜单、筛选、打开详情、关闭弹框、截图可以做；保存、编辑、审批、资金、账号状态变更必须停下确认。
质量门禁 Multica 完成后，由复验专家复查关键结论；Codex 负责收口到本地 Dashboard 和发布校验。

当前要加强的点

问题 改进动作 验收标准
产物散落，用户不知道从哪看 所有 Multica 输出必须登记进 Dashboard 的需求列表、问题轨迹、下载与分享。 打开 Dashboard 就能看到当前需求、历史问题、报告和压缩包。
测试进度看起来静默 Multica issue 内按阶段回复：疑问闸门、测试设计、执行中、Bug 提炼、复验、发布。 超过一个阶段没有产物时，必须说明卡点或下一步动作。
Bug 数量和有效状态容易混淆 Dashboard 区分“历史问题记录”和“当前有效 Bug”。 历史 3 条问题可以追溯；当前有效 Bug 为 0 时也能解释原因。
误报风险 引入 QA 复验专家，所有 Bug 关闭、非 Bug、未复现都必须二次确认。 对外发给开发前，Bug 单有明确结论和证据截图。
