VIP管理查看会员Tab - 测试设计

Issue：WS-12 独立对照测试：【站点】VIP管理增加查看会员tab

设计结论：疑问闸门已放行，无需求阻塞；可进入只读浏览器执行。

后台入口：http://site.bx-tytest.xyz；路径：福利中心 / VIP管理 / 查看会员；可能路由：#/member/level

H5入口：https://99.bx-1234.xyz/#/dashboard/game；本轮仅在发现跨端影响时做只读观察。

执行边界：允许导航、查看、点击列表数字、打开/关闭详情弹框、分页/筛选、截图；禁止保存、提交、删除、审批、导出、充值、提现、奖励发放、会员状态变更；不处理密码、验证码、OTP。

测试范围

范围项本次覆盖不覆盖/限制
菜单与Tab入口 验证后台路径可达，VIP管理中存在新增“查看会员”tab，路由/面包屑/当前tab状态清晰。 不测试菜单权限配置后台写入；无登录态时记录为执行阻塞。
VIP等级列表 验证等级列表按当前配置展示，包含等级标识、名称、成员数量等用于查看会员的关键列。 不直接判定 VIP 名称与 grade 映射差异为 bug，除非页面上下文自相矛盾。
成员数量与详情入口 验证成员数量大于 0 时可点击并打开明细；数量为 0 时不可点击且不弹框。 若系统没有可核对的总数来源，只记录页面内一致性，不扩展到数据库核验。
查看会员弹框/明细 验证弹框标题、VIP等级上下文、表格字段、分页、筛选、空数据、关闭后列表状态。 不执行导出、会员状态变更或任何写操作。
跨端影响 仅当后台观察发现会员等级/数量异常可能影响 H5 展示时，做 H5 只读观察。 不做 H5 充值、提现、领奖、游戏下注等敏感动作。

最小测试闭环

  1. 打开后台并确认是否已有登录态；无登录态或验证码阻断时，停止执行并输出阻塞报告。
  2. 进入福利中心 / VIP管理，切换到“查看会员”tab。
  3. 记录 VIP 等级列表展示字段、等级行数、成员数量分布，至少覆盖一个数量大于 0 的等级和一个数量为 0 的等级；若没有 0 或大于 0 数据，按实际数据记录覆盖缺口。
  4. 点击数量大于 0 的成员数量，检查会员明细弹框/列表与来源 VIP 等级上下文一致，检查分页、筛选、关闭后的列表状态。
  5. 点击或尝试聚焦数量为 0 的成员数量，确认不可点击、不弹框、不触发错误提示。
  6. 汇总 bug、残余风险、与本地既有结论是否一致，写入执行报告。

Seam与检查点

Seam检查点通过口径失败口径
菜单/路由 seam 后台路径、tab名称、路由、页面加载状态。 路径可达，tab存在且进入后页面语义与“查看会员”一致。 入口缺失、tab无法进入、进入后仍为旧页面或报错。
VIP配置到列表 seam VIP等级列表是否按配置完整展示。 等级行完整，关键字段可识别，排序/层级不造成业务误读。 等级缺失、重复、字段为空导致无法判断会员归属。
列表数量到明细 seam 成员数量与点击行为、弹框明细总数/分页总数的一致性。 数量大于 0 可查看，弹框记录与列表数量在页面可见口径内一致。 大于 0 不可查看、0 可打开弹框、明细明显与来源等级或数量不一致。
来源上下文 seam 弹框标题、筛选条件、VIP等级字段与点击来源。 弹框明确展示当前等级上下文，筛选后不串级。 点击 A 等级展示 B 等级会员，或弹框上下文丢失导致无法确认来源。
弹框状态 seam 分页、筛选、空数据、关闭后列表保留状态。 操作只影响弹框内部，关闭后列表页不异常刷新、不丢失关键状态。 分页/筛选报错、空数据异常、关闭后列表错乱或页面不可用。

ID用例前置/数据步骤预期证据要求
BR-01 后台入口与查看会员tab存在 后台已有登录态；站点：巴西站/测试；商户：888。 进入后台，按路径打开福利中心 / VIP管理，切换查看会员tab。 tab存在、可切换、页面无报错，当前页面是会员查看语义。 页面全屏截图；记录路由和tab文案。
BR-02 VIP等级列表展示 查看会员tab可打开。 观察等级列表行、关键列、成员数量列。 等级列表完整展示，成员数量列可读，数量格式稳定。 列表截图；记录可见等级、数量分布。
BR-03 成员数量大于0时查看明细 至少存在一行成员数量大于0。 点击该行成员数量，打开会员明细。 明细可打开，来源 VIP 上下文清晰，明细记录/总数与列表数量在页面口径内一致。 点击前列表截图；弹框/明细截图；记录来源等级、数量、弹框总数。
BR-04 成员数量为0时不可打开明细 至少存在一行成员数量为0。 点击或尝试点击该行成员数量。 成员数量不可点击或点击无弹框，无错误弹窗、无空明细误导。 0数量行截图；点击后页面状态截图。
BR-05 明细分页 大于0等级的明细有多页，或页面显示分页控件。 在明细内切换页码/每页条数，只做只读分页。 分页控件正常，数据仍限定在来源 VIP 等级上下文内。 分页前后截图；记录页码、总条数。
BR-06 明细筛选与空数据 明细提供只读筛选项。 使用安全筛选条件查询；再输入不存在条件触发空数据。 筛选结果不串级；空数据有正常占位，无报错。 筛选条件、结果截图；空数据截图。

BR-08 跨端只读观察 仅当后台数据异常疑似影响 H5 VIP 展示时执行。 打开 H5 dashboard/game，只读观察会员/VIP相关展示是否受影响。 不做敏感动作；仅记录是否存在明显跨端展示异常。 H5只读截图；说明触发该用例的后台异常。

不交给浏览器执行的判定项

ID判定项原因报告保留口径
NB-01 数据库级成员数量准确性 本轮没有数据库/接口授权，也不应绕过系统只读页面。 若页面无第二口径可核对，只能判定“页面内一致/不一致”，保留“未做数据库核验”的残余风险。
NB-02 VIP名称与grade映射最终产品口径 issue已明确存在产品/后端口径差异时不武断判bug。 报告中记录实际展示与来源上下文；映射歧义标为待确认或非bug判断依据。
NB-03 权限配置写入、菜单授权变更 涉及后台配置写操作，超出只读边界。 仅记录当前账号可见性；不覆盖不同角色权限矩阵。
NB-04 导出、保存、审批、删除等写操作 issue明确禁止敏感/不可逆操作。 执行报告保留“未覆盖导出/写操作”的边界说明，不作为本需求通过阻塞。
NB-05 登录、验证码、OTP处理 不处理密码、验证码、OTP。 无登录态时输出阻塞，不尝试登录；风险归因为环境/账号可达性。

测试数据要求

数据类型最低要求缺失时处理
成员数量大于0的VIP等级 至少1个，用于验证明细入口、弹框上下文、分页/筛选。 记录覆盖缺口；若全为0，只能完成0数量不可点击和列表展示检查。
成员数量为0的VIP等级 至少1个，用于验证不可点击、不弹框。 记录覆盖缺口；不伪造数据，不执行配置写入。
多页明细数据 优先选择数量超过单页容量的等级。 若没有多页数据，分页用例标记未覆盖并保留残余风险。
可触发空数据的筛选条件 使用页面允许的只读筛选字段输入不存在会员标识。 若无筛选项或筛选会触发敏感操作，则不执行并记录边界。

风险矩阵

风险影响概率测试处理报告口径
无登录态/验证码阻断 高中5分钟内无法推进即停止。执行阻塞，说明卡在登录态/验证码，不尝试登录。
缺少0或大于0的数据 中中按实际可见数据覆盖。保留数据覆盖不足风险，不造数。
成员数量缺少外部核对口径 高中用列表数量、弹框总数、分页总数做页面内一致性核对。不能宣称数据库级准确，只能说明页面内一致性。
VIP名称与grade映射歧义 中中观察来源等级与弹框上下文是否自洽。映射差异不直接判bug，除非造成明显串级或上下文错误。
跨端影响未触发 低低仅后台发现异常时执行H5只读观察。未触发时说明H5未覆盖，不影响后台主验收。

自动化优先级

优先级候选场景理由
P0 查看会员tab存在、列表加载、数量大于0可打开明细、数量为0不弹框。 核心验收点稳定、回归价值高、只读执行安全。
P1 弹框上下文、分页、关闭后状态。 影响使用体验和串级风险，但依赖数据量。
P2 筛选空数据、H5跨端只读观察。 依赖页面控件和触发条件，作为补充回归。
不建议自动化 验证码登录、权限配置变更、导出/写操作、数据库核验。 超出只读边界或依赖敏感凭据/外部权限，不适合本轮浏览器自动执行。

低价值不测区

  • 逐像素UI样式、颜色、间距，不影响入口存在和会员查看业务判断时不作为本轮重点。
  • 无业务差异的重复VIP等级逐行点击；优先覆盖0、大于0、多页、空数据这些等价类。
  • 非本需求链路的H5玩法、钱包、充值、提现、奖励发放。
  • 后台写配置、导出和审批类操作。

执行报告必须保留的残余风险口径

残余风险必须写入报告的口径
数据库级数量准确性 本轮只读页面核验；如无接口/数据库/独立统计口径，不宣称数据库级准确，仅记录列表数量与明细总数/分页总数是否一致。
VIP名称与grade映射 映射差异按待确认处理；只有来源等级与弹框/明细发生明显串级时才作为bug候选。
数据覆盖不足 若环境缺少0数量、大于0数量或多页数据，明确列出未覆盖用例，不用“通过”替代“未覆盖”。
权限/登录态限制 无登录态、验证码、OTP、权限不足导致无法进入时，输出阻塞原因和停留步骤，不尝试处理敏感凭据。
禁止操作未覆盖 导出、保存、提交、删除、审批、充值、提现、奖励发放、会员状态变更均未覆盖，且不作为本轮通过/失败依据。
跨端影响 H5只在后台异常疑似外溢时观察；未触发时报告应写明H5未作为主验收链路。
