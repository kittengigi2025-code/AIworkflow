QA 产物目录与整理规则

入口文件：qa-index.html 原则：正式产物只认 HTML 最后更新：2026-07-08

管理原则

一个总入口 .scratch/qa-index.html 是唯一入口。新增 HTML 产物必须从这里能点到。
每个需求一个目录 需求相关文件放到 .scratch/<需求slug>/，只保留 test-report.html、bug-tickets.html、evidence/ 等当前产物。
流程资产单独管理 流程、Multica、资源卡片、复盘这类跨需求文件放在顶层，并在本目录页登记。
旧 Markdown 不再当正式产物 旧 .md 只作为历史草稿。若内容已进入 HTML，可以归档；不再从 QA index 直接暴露给团队。
临时下载文件要标记 Axure 或页面下载的 .js 这类文件不能混在正式报告视图里，后续移动到 tmp/ 或归档。

推荐目录结构

路径 用途
.scratch/qa-index.html 总入口，展示所有测试需求、资源、流程资产和操作手册。
.scratch/artifact-catalog.html 产物目录，说明哪些文件是当前有效、哪些建议归档。
.scratch/test-resources.html 环境与测试资源卡片，由 QA资源管理员 维护。
.scratch/system/ 后续建议放流程资产：Multica 操作、军团说明、复盘、skill 源文件。
.scratch/requirements/<date>-<slug>/ 后续建议放每个需求的报告、Bug 单、证据、回归记录。
.scratch/archive/ 历史草稿、旧 Markdown、临时下载文件。移动前应先确认不再被当前 HTML 链接。
