确认的验收规则

规则 ID 规则 判定口径
R-01 VIP 列表顺序 列表中的 VIP 等级必须按从低到高展示，例如 1、2、3、4；不得出现 2 在 1 前、10 被排在 2 前的字符串排序问题。
R-02 VIP 等级展示 展示值读取 VIP 配置，VIP1 展示为 1、VIP2 展示为 2；验证展示值与配置含义一致，不把等级名、ID、排序号混用。
R-03 成员数量统计 成员数量展示该 VIP 等级下会员数量；数量应与点击后弹框内会员总量或可见分页总量一致。
R-04 非 0 成员数量样式与交互 非 0 数字显示为蓝色，具备可点击态；点击后打开查看会员弹框，弹框上下文必须对应当前 VIP 等级。
R-05 0 成员数量样式与交互 0 不可点击，不应显示为可点击蓝色；点击或误触不应打开查看会员弹框，不应改变页面状态。
R-06 弹框展示全状态会员 查看会员弹框展示该 VIP 等级下所有状态的会员，不能只展示启用、正常或某单一状态会员；如有筛选项，默认不得隐藏其他状态。

最小测试闭环

  1. 人工准备后台登录态，打开后台并确认站点为“巴西站-测试”、商户为“888”。
  2. 进入“福利中心 / VIP管理 / 查看会员”或路由 #/member/level。
  3. 截图记录 VIP 列表首屏，验证等级列是否按数值从低到高展示。
  4. 找到至少一个成员数量为 0 的 VIP 行，验证样式不可点击，点击不弹框。
  5. 找到至少一个成员数量非 0 的 VIP 行，验证数字为蓝色可点击，点击弹出查看会员弹框。
  6. 在弹框中核对等级上下文、会员列表、状态列、分页总数或总条数。
  7. 如弹框支持状态筛选，仅做只读切换验证全状态可见性，不执行保存或修改。
  8. 关闭弹框后再点击另一个非 0 等级，确认弹框上下文不会沿用上一等级。

测试数据要求

数据类型 最低要求 用途
VIP 等级 至少 3 个等级；最好包含 VIP1、VIP2、VIP10 或更高等级。 验证数值升序，防止字符串排序导致 VIP10 排在 VIP2 前。
0 成员等级 至少 1 个成员数量为 0 的等级。 验证 0 数量样式不可点击、点击不弹框。
非 0 成员等级 至少 1 个成员数量大于 0 的等级。 验证蓝色可点击、弹框打开、数量一致。
多状态会员 同一 VIP 等级下尽量存在正常、禁用、冻结或其他可见状态会员。 验证弹框默认展示全状态会员，不只显示正常会员。
分页数据 如某等级会员数超过单页条数，保留该等级作为分页样本。 验证弹框分页总数、翻页后等级上下文和状态集合不丢失。

自动化优先级

优先级 候选项 原因与边界
P1 VIP 等级数值升序校验 稳定、只读、低成本；适合页面列表自动抓取后做数值断言。
P1 0/非 0 成员数量样式与弹框行为 核心验收点，适合用只读 UI 自动化校验；需人工或环境预置登录态。
P2 弹框数量与入口数量一致 需处理分页和总数口径，自动化前要固定页面总数字段。
P2 全状态会员展示 依赖测试数据具备多状态会员；可在数据稳定后纳入回归。
暂不自动化 登录、验证码、账号准备、会员状态造数 涉及凭据、验证码或状态变更；保留为人工准备或后端安全测试数据流程。

低价值不测区

  • 不做按钮像素级颜色差异测试；只判断非 0 是否明显为蓝色可点击态、0 是否非可点击态。
  • 不测试 VIP 配置新增、编辑、保存链路；本需求关注列表展示和查看会员。
  • 不测试数据库真实统计 SQL；执行阶段只用页面可见总量与弹框总量做黑盒核对。
  • 不测试导出、批量操作、状态修改、奖励发放、充值提现等与本需求无关且高风险操作。
  • 不编写依赖具体 DOM 层级或坐标的脆弱点击脚本；后续自动化应优先使用文本、列名、角色和稳定选择器。
