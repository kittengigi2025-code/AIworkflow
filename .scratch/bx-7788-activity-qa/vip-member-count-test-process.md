# VIP 管理成员数量标准测试流程

Status: ready-for-agent

## Purpose

把昨天的最高层测试闭环应用到 `VIP 管理 / 查看会员 / 会员数量` 需求上，避免只测一个 tab 或一个数字。这个流程验证 `会员层级` 数据是否能支撑后续活动参与限制、H5 展示和奖励/稽核判断。

## Test Seam

Primary seam:

`管理后台 VIP 管理 -> 会员数量 -> 查看会员 tab -> 会员层级参数 -> 活动配置引用会员层级 -> H5 活动展示/参与限制`

Use browser-visible behavior and request evidence as the public interface. Do not verify by directly querying the database.

## Normalized Flow

### 1. 后台确认 VIP 层级基线

Goal:
确认 VIP 管理页能展示各会员层级，并且每个层级有可理解的成员数量。

Steps:

1. 登录管理后台。
2. 进入 VIP 管理。
3. 记录至少两个会员层级：一个有会员数量，一个不同 `vipGrade` 的层级。
4. 记录每个层级的会员数量。

Expected:

- VIP 层级列表可见。
- 成员数量可见。
- 成员数量为数字，允许为 `0`。
- 有会员数量的数字应可进入查看会员路径。

Evidence:

- VIP 层级名称或等级。
- 成员数量。
- 当前站点或 `siteId` 上下文。

### 2. 点击成员数量进入查看会员 tab

Goal:
确认成员数量不是装饰数字，而是进入该层级会员列表的业务入口。

Steps:

1. 点击 VIP A 的成员数量。
2. 观察是否进入或切换到「查看会员」tab。
3. 查看会员列表加载完成。

Expected:

- 当前页面处于「查看会员」tab。
- 列表只展示 VIP A 层级下的会员。
- 列表总数与 VIP A 的成员数量一致，或在有搜索条件时小于等于成员数量。

Evidence:

- tab 名称。
- 列表总数。
- 至少一条会员记录的会员账号或会员 ID。
- 请求参数中的 `siteId`、`vipGrade`、`curPage`、`pageSize`。

### 3. 切换另一个 VIP 层级防止参数串用

Goal:
覆盖截图评论里暴露的核心风险：第一次点击 VIP A 后，再点击 VIP B，前端仍然带 VIP A 的参数。

Steps:

1. 从 VIP A 的查看会员结果返回 VIP 管理列表，或以产品支持的路径选择 VIP B。
2. 点击 VIP B 的成员数量。
3. 观察「查看会员」tab 重新加载。
4. 对比 VIP A 与 VIP B 的请求参数。

Expected:

- 第二次请求的 `vipGrade` 必须是 VIP B。
- `siteId` 必须仍是当前站点。
- `curPage` 应重置为 `1`，除非产品明确要求保留分页。
- 列表数据不能沿用 VIP A。
- 列表总数应与 VIP B 的成员数量一致，或在有搜索条件时小于等于成员数量。

Evidence:

- VIP A 请求参数。
- VIP B 请求参数。
- 两次列表的会员账号或空态截图。
- 如果 VIP A 与 VIP B 数量不同，记录数量差异。

### 4. 空层级与分页边界

Goal:
确认无会员层级和分页不会破坏当前 `vipGrade`。

Steps:

1. 选择成员数量为 `0` 的 VIP 层级，或找一个低数量层级。
2. 点击成员数量或进入查看会员 tab。
3. 如果列表超过一页，切换页码或 pageSize。

Expected:

- `0` 成员层级显示空态，不报错。
- 空态仍能看出当前层级上下文。
- 翻页或修改 pageSize 后仍保持当前 `vipGrade`。
- 切换 pageSize 后不要回到上一个 VIP 层级。

Evidence:

- 空态截图。
- 翻页前后请求参数。
- pageSize 修改前后请求参数。

### 5. 与活动会员层级限制串联

Goal:
把 VIP 管理能力接回昨天的活动 QA 地图，证明这个功能能支撑活动资格判断。

Steps:

1. 选择一个已知会员所在的 VIP 层级。
2. 在活动配置中确认或创建一个按该会员层级限制的活动。
3. 使用该层级会员登录 H5 前台。
4. 查看 H5 活动列表和活动详情。
5. 使用另一个非该层级会员登录 H5 前台，对比展示或参与状态。

Expected:

- 当前层级会员可以看到或参与该活动。
- 非当前层级会员不可见、不可参与，或收到明确限制提示。
- 后台 VIP 管理的查看会员结果与 H5 活动资格表现一致。

Evidence:

- VIP 查看会员 tab 中的会员。
- 活动配置中的会员层级限制。
- H5 活动列表或活动详情对比截图。

## P0 Checklist

- VIP 管理列表展示成员数量。
- 点击成员数量进入「查看会员」tab。
- 查看会员请求带正确 `siteId`。
- 查看会员请求带正确 `vipGrade`。
- 点击 VIP A 后再点击 VIP B，`vipGrade` 不串用。
- 切换 VIP 层级后 `curPage` 重置为 `1`。
- 查看会员列表总数与成员数量一致，或在搜索过滤时符合小于等于关系。
- 成员数量为 `0` 时显示空态，不报错。
- 活动配置按会员层级限制时，H5 展示/参与结果与查看会员 tab 中的会员层级一致。

## P1 Checklist

- 查看会员 tab 内按会员账号或会员 ID 搜索。
- 搜索条件不会污染 VIP 管理列表的成员数量。
- tab 来回切换后保持当前层级上下文。
- 刷新页面后默认状态清晰，不误用上一次 `vipGrade`。
- 不同站点之间 `siteId` 不串。
- 权限不足账号不能查看超出权限范围的会员信息。

## Known Product Questions

- 成员数量统计全部会员，还是只统计正常/启用会员？
- 冻结、禁用、注销会员是否计入成员数量？
- 成员数量为 `0` 时数字是否可点击？
- 直接点击「查看会员」tab 且未选择 VIP 层级时，默认显示全部会员、当前层级，还是空态？
- `vipGrade` 是展示等级编号，还是后端层级主键？
- 会员升降级后，成员数量是否实时刷新？
- 活动配置引用的是 `vipGrade`，还是 VIP 层级 ID？

## Low-Value Areas

- 不重复验证每个表格列的排序和宽度。
- 不对所有 VIP 层级做全排列，只选代表性层级：有会员、无会员、不同 `vipGrade`。
- 不做像素级 UI 对比。
- 不把分页组件本身作为重点，除非分页导致 `vipGrade` 丢失或串用。
