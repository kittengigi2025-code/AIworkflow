## 需要产品确认的问题

### Q1. 点击成员数量后的 VIP 筛选框应该显示什么？

背景：

- 在 `查看会员` tab 中点击 VIP1 成员数量后，成员明细行内显示 `VIP等级 = 1`，但弹窗顶部筛选框显示 `VIP0`。
- 点击 VIP2 成员数量后，成员明细行内显示 `VIP等级 = 2`，但弹窗顶部筛选框显示 `VIP1`。

请产品确认：

- 弹窗顶部 VIP 筛选框是否应该显示被点击的等级？
- 例如点击 VIP1，筛选框是否应显示 `VIP1`？
- 如果显示 `VIP0` 是预期，请说明 `VIP0` 和行内 `VIP等级 = 1` 的业务映射关系。

影响：

- 影响是否判定为前端展示 bug。
- 影响后续自动化断言应该断言 `VIP1` 还是 `VIP0`。

### Q2. `vipGrade` 的编号规则是什么？

请产品/开发确认：

- `vipGrade` 是从 0 开始，还是从 1 开始？
- 它是展示等级、后端枚举值，还是 VIP 层级 ID？
- 活动配置里的会员层级限制使用的是同一个 `vipGrade`，还是另一个层级 ID？

影响：

- 影响 VIP 管理、活动配置、H5 活动资格判断是否可以串联验证。
- 影响接口参数和 UI 展示不一致时如何定责。

### Q3. 成员数量的统计口径是什么？

请产品确认成员数量是否包含：

- 冻结会员
- 禁用会员
- 注销会员
- 测试会员
- 待审核或异常状态会员

影响：

- 影响成员数量与明细总数是否必须完全一致。
- 影响后台会员查询与 VIP 成员数量是否可以交叉核对。

### Q4. 成员数量为 0 时应该如何交互？

请产品确认：

- `0` 是否可点击？
- 点击后是否进入成员明细空态？
- 还是数字置灰/不可点击？
- 空态文案是否有要求？

影响：

- 影响 VIP10 等 0 成员层级的测试期望。

### Q5. 直接点击 `查看会员` tab 时默认展示什么？

请产品确认：

- 未从某个 VIP 成员数量进入，而是直接点击 `查看会员` tab 时，默认展示全部会员、空态、还是某个默认 VIP 等级？
- 如果之前查看过某个 VIP，再切回 tab，是否应保留上一次等级？

影响：

- 影响“状态保留”和“参数串用”的判定。

6. 0 成员等级交互符合产品确认口径。
7. 分页、搜索、刷新后保持正确 `siteId` 和 VIP 等级上下文。
