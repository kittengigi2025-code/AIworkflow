核心原则

原则说明
疑问先行需求规则不清楚时，先由需求澄清员输出阻塞问题，不带着问题执行。
只读执行浏览器执行只做导航、查询、详情、弹框、截图；不保存、不提交、不导出、不改业务状态。
复验门禁测试报告和 Bug 单发布前，必须经过测试复验专家抽查；高风险结论必须复验。
HTML 交付正式结果统一输出 HTML：测试报告、Bug 单、关闭说明、回归报告、台账。

复验专家介入规则

场景复验动作输出
新增 Bug 复查需求依据、复现步骤、截图证据、操作命中点、网络/环境瞬时状态可能性。 通过 / 需补证 / 推翻 Bug。
回归通过或失败 抽查失败点或修复点是否真正覆盖，确认报告、Bug 单、台账状态一致。 回归复验报告 HTML。
未复现 确认是否真的覆盖原复现路径；不能只因为一次没看到就关闭。 未复现说明或继续观察建议。
产品/后端接受为非 Bug 检查是否有明确口径，报告中是否把非 Bug 和残余风险分开。 口径确认记录。
站点/台账发布 检查首页、台账、内部看板、脱敏看板、下载包是否使用同一结论。 发布前门禁结论。
